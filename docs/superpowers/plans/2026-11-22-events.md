# Events and Situations Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Twelve kinds of Stellaris-style event, about fifteen a game, none very harmful, with an
Event window and a Situations list whose every action item takes the player to the spot.

**Architecture:** The events are data (`src/data/events.json`, a content table). An `EventDesk` in
`src/sim/events.ts` picks them once a game day, from a generator made from the seed and the day.
It keeps open cases, running effects and a log in the save, and answers three multipliers that
`SimStep` and `HouseRegistry` read. Projects are contracts. Open cases become notices with targets,
so the alert bar, pins and `Game.focusNotice` lead to them. The UI is two kit screens over pure
view modules.

**Tech Stack:** TypeScript strict, Vite, PixiJS v8 (untouched), vitest under Node.

**Spec:** `docs/superpowers/specs/2026-10-31-events-design.md`

## Global Constraints

- No runtime dependency. No `Math.random` in the simulation: every draw is from `Rng`.
- Every player-facing string is in `src/strings.ts` and in `src/data/strings.hu.ts`, key for key.
  Effect lines are built from the data, so the number shown is the number applied.
- Content is data: the twelve events live in `src/data/events.json` as the content table `events`.
- The first choice of every event is free: no cost, no project, no lot.
- A bad effect is at most -20 % and lasts at most one season. Only good effects last for good. An
  event takes no money and no goods unless the player picks it.
- Money goes through `economy.spend(v)`, never `economy.charge` or `money -=`. Goods go through
  `payEvent` and `giveEvent` in `src/sim/eventPay.ts` only, on `stores.selected`. When resource
  modes (#306) merge, Hard mode uses `stores.nearest(x, y)[0]` there, and nowhere else changes.
- The auction's price is half of `cargoDef(id).price`, never the market price.
- `src/sim/trafficSoak.test.ts` goldens must not change. If they do, the change is wrong.
- Saves: one top-level key `events`, the next free `SAVE_VERSION` on develop at the time of the
  task (24 today; #624 and the bridge and wear stacks also claim numbers), a migration step that
  fills in the empty state, and `events` in `KNOWN_SAVE_KEYS`.
- Numbers: first event day 5; gap 7 to 13 days divided by `rules.eventRate`; a kind not again
  within 40 days; a decision lapses to its first choice after 3 days; a discovery 1 in 4;
  `EVENT_MIN_INCOME` 300; the log keeps 50.
- Commands start with `export TEMP=G:/DEV/wt/_tmp TMP=G:/DEV/wt/_tmp TMPDIR=G:/DEV/wt/_tmp`. Run
  vitest with `--maxWorkers=2`, one gate at a time. Never use port 5266.
- Run `npm ci` once in `G:/DEV/wt/events` before the first task.
- Commit subjects are `Area: outcome`, ending with the `Co-Authored-By` line.
- Paths cross roles (gameplay, uiux, engine, core docs): the PR needs the `scope:cross` label.

## Review Focus

1. **A save made mid-event** (an open decision, a running effect, a project under way) loads into
   the same state, and the next event is the one it would have been. Test in Task 5.
2. **The site goes while a case is open** (the town's station demolished, the farm removed): the
   case closes, its action item goes, nothing throws. Test in Task 3.
3. **The player cannot pay any more when choosing** (money spent since the window opened): the
   choice is refused with its reason and nothing changes; the 3-day lapse to the free first choice
   always succeeds. Test in Task 3.
4. **Game speed and pauses** do not change which events come or when. Test in Task 5.
5. **An event fires behind a menu or while paused:** the window waits and never resumes a
   paused game. Test in Task 8.

Rules per kind: `river`, track with a `Biome.River` tile within 2; `hills`, track on or next to

of a `Map` never decides. `skipChunks` drops candidates in those chunks (the stone bank).

```ts
  money: number;
  goods: Record<string, number>;
}

export const EVENT_FIRST_DAY = 5;
export const EVENT_GAP: readonly [number, number] = [7, 13];
export const EVENT_COOLDOWN_DAYS = 40;
export const EVENT_DECIDE_DAYS = 3;
export const DISCOVERY_ODDS = 0.25;
export const EVENT_MIN_INCOME = 300;
export const EVENT_LOG_CAP = 50;
export interface EventCase {
  id: number;
  defId: string;
  day: number;
  site: EventSite;
  /** null: waiting for a choice */
  choice: number | null;

  day: number;
  defId: string;

  check(caseId: number, choice: number): ChoiceCheck;
  choose(caseId: number, choice: number): ChoiceCheck;
  incomeScale(): number;
  productionMul(s: Station): number;

```

How `newDay` works, in this order: sample `economy.earned` for the income scale (the last 5 day
starts); close cases whose site is gone (`siteAlive`) and drop their effects; end effects whose
`until` has come; lapse decisions past `decideBy` to choice 0; fire chain follow-ups due today;
then, from `EVENT_FIRST_DAY` on and on or after `nextDay`, pick. The day's generator is
`new Rng((seed ^ 0xe7e47 ^ Math.imul(day, 0x9e3779b1)) >>> 0)`; a discovery's is the same with salt
`0xd15c0` and the chunk index. Eligible: not a discovery, `needs` met, season fits
(`seasonOf(day)`), not within `EVENT_COOLDOWN_DAYS` of its last firing, not trouble right after
trouble, and `findSite` finds a site. Weighted pick in table order. A fired event sets `nextDay`
to `day + max(1, round(rng.int(7, 13) / rules.eventRate))`; with none eligible, `nextDay` is
tomorrow. `rules.eventRate` 0 fires nothing. News (no choices) applies its `fire` effects and
closes at once. Income: `(earned now - earned 4 day starts ago) / 4`, at least `EVENT_MIN_INCOME`.
A choice's money cost is `income × incomeScale()`, rounded; goods are scaled per piece when
`perPiece`. `span: 'season'` ends on `day + daysUntilNextSeason(day)`. `lot` buys the scarcest of
wood, stone, iron, coal and food in `stores.selected` (lowest `get / cap`, ties in that order), as
many units as `income × incomeScale()` buys at the base price, paid at half of it.

project contracts to the dispatcher as it does any accepted contract.
